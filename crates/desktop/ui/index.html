Runs on your robot host

ROS 2 · Battery observations

Use the nexa-robot CLI on a Linux host with ROS 2 installed. This Mac does not read a remote ROS graph.

  1. Build nexa-robot from the matching Bridge source on the ROS host: cargo build --release --locked -p nexa-robot. Use target/release/nexa-robot below or add that directory to your PATH.
  2. Source your ROS environment and check one local voltage reading.
  3. Pair that host in your browser, then send an observation to the approved workspace.
Host commands and supported reading

Replace the example origins, state path and workspace with your deployment. Run these commands on the ROS host.

source /opt/ros/jazzy/setup.bash
nexa-robot inspect-ros-battery
mkdir -m 700 "$HOME/.nexa-hardware"
nexa-robot pair-ros-battery \
  "$HOME/.nexa-hardware/robot.json" \
  https://api.example.com https://agora.example.com \
  "workshop/robot/battery"
# Approve the endpoint in your browser first.
nexa-robot observe \
  "$HOME/.nexa-hardware/robot.json" my-workspace

Reads only /battery, sensor_msgs/msg/BatteryState.voltage. No continuous ROS streaming, camera feeds, remote shell or actuator commands. The host CLI sends one observation per invocation.
